# Курс «Backend-разработка»: как всё устроено

За семестр собирается **один проект** по своей теме. Сначала это HTTP-сервис, потом к нему добавляются база данных, пользователи и права, веб-страница с защитой от атак, Docker и второй сервис. Каждая лаба добавляет новый слой в тот же репозиторий, а на последней встрече проект защищается как готовый продукт.

Кроме основного слоя, в каждой лабе есть небольшие задачи на технологии, которые встречаются почти в любом бэкенде: менеджер пакетов, документация API, индексы, поиск, JWT, OAuth, заголовки безопасности, обновления в реальном времени, Nginx, Redis, очередь сообщений, CI и деплой. Каждая такая задача занимает от часа до вечера.

| Лаба | Что добавляется | Звёздочки | Задание |
| --- | --- | --- | --- |
| 1 | HTTP-сервис, данные хранятся в памяти, зависимости в файле | Единый формат ошибок, пагинация; OpenAPI и лог запросов | [lab-1.md](lab-1.md) |
| 2 | База данных, вторая сущность, схема из репозитория | Миграции, индекс и EXPLAIN, поиск; правило темы в транзакции, статистика | [lab-2.md](lab-2.md) |
| 3 | Пользователи, хэши паролей, права доступа (401, 403) | JWT; админ и лимит попыток | [lab-3.md](lab-3.md) |

| 5 | Docker, второй сервис, проект запускается одной командой | CI и Nginx; два из трёх: Redis, брокер сообщений, деплой | [lab-5.md](lab-5.md) |

Темы проектов собраны в [themes.md](themes.md). Язык бэкенда любой: Python, JavaScript или TypeScript, Go, Java, C#, PHP. Проверяется поведение API, а не язык и не стиль кода.

## Баллы

| Что | Максимум |
| --- | --- |
| Посещение | 8, по 1 баллу за встречу |
| Лабы | 60, это 5 лаб по 12 баллов |
| «Своя игра» | 10 |
| Защита проекта | 22 |
| Всего | 100 |

| Баллы | Оценка |
| --- | --- |
| 86-100 | 5 |
| 76-85 | 4 |
| 61-75 | 3 |
| 60 и меньше | 2 |

**Одна лаба стоит 12 баллов:**

| Часть | Баллы | Как ставится |
| --- | --- | --- |
| Чек-лист базы | 6 | 6 пунктов, каждый либо работает (1 балл), либо нет (0) |
| Вопрос к лабе | 2 | 2: ответ сам; 1: с подсказкой; 0: нет ответа |
| ★ | 2 | 2: всё работает; 1: работает половина; 0: нет |
| ★★ | 2 | Так же, как ★ |

Лаба **принята**, если в чек-листе работает хотя бы 4 пункта из 6 и автор может объяснить свой код. Звёздочки смотрят только у принятой лабы.

Без звёздочек можно набрать максимум 80 баллов, это «4». Для «5» нужны звёздочки.

**«Своя игра»** проходит на встрече 7: три команды отвечают на вопросы по всему курсу. За первое место каждый в команде получает 10 баллов, за второе 7, за третье 4. Кто пропустил игру, пишет мини-викторину из 10 вопросов: 7 верных и больше дают 4 балла.

**Защита** на встрече 8: 5 минут рассказа с живой демонстрацией и 2 вопроса. Оценивается, работает ли проект (8 баллов), понимает ли автор, как он устроен (6), понятно ли, кому и зачем он нужен (4), и как построено выступление (4). К защите допускаются те, у кого приняты лабы 1, 2 и 3.

## Как сдавать

Каждая лаба сдаётся через Pull Request (PR). Это запрос на то, чтобы влить изменения из одной ветки в другую. В PR видно, что изменилось, и там же ставится оценка.

1. Для каждой лабы создаётся своя ветка от `main`: `lab-1`, `lab-2` и так далее.
2. Проверить себя чекером: [backcheck](https://github.com/bozhedom/backcheck).
3. Когда всё готово: PR из ветки `lab-N` в `main`, в описании PR отмечается чек-лист.
4. На паре: запустить сервис, показать работу и ответить на вопрос к лабе. После приёма PR вливается в `main`.

```bash
git switch main
git pull
git switch -c lab-2
# работа над лабой
git add .
git commit -m "Лаба 2: PostgreSQL, вторая сущность"
git push -u origin lab-2
# дальше на GitHub кнопка «Compare & pull request»
```

## Сроки

- **Дедлайн**: PR открыт до 23:59 накануне встречи, на которой лабу принимают. В 23:59 записывается, какой коммит был в PR. Всё, что добавлено позже, считается опозданием.
- **Не успели принять на паре** из-за очереди: лабу принимают в начале следующей встречи без потери баллов. Срок определяет время PR, а не очередь.
- **PR открыт после дедлайна** или **повторная сдача** после «не принята»: засчитывается только база, до 8 баллов.
- **Последний срок для всех долгов**: встреча 7. После неё несданная лаба остаётся с нулём.
- **Допуск к защите**: приняты лабы 1, 2 и 3.
