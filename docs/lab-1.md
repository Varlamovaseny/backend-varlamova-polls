# Лаба 1. HTTP CRUD в памяти

HTTP-сервис для главной сущности своей темы: создание, получение, изменение и удаление записей по правилам REST. Данные хранятся в памяти программы. У сущности 3-5 полей: хотя бы одно обязательное строковое и одно число или статус, `id` ставит сервер. Путь `/api/<сущности во множественном числе>`, порт 8000. Язык и фреймворк любые.

Срок: PR из `lab-1` в `main` до 23:59 накануне встречи 2.

## Чек-лист базы (6 баллов)

1. README (тема, как запустить, таблица эндпоинтов), `requests.http` со всеми запросами, файл зависимостей
2. `GET /health` отвечает 200 и `{"status": "ok"}`
3. `POST /api/<items>` отвечает 201 и возвращает объект с `id`
4. `GET /api/<items>` и `GET /api/<items>/{id}` работают, неизвестный id даёт 404
5. `PUT` или `PATCH` обновляет, `DELETE` отвечает 204, после удаления `GET` даёт 404
6. Сломанный JSON или пустое обязательное поле дают 400, а не 500 и не падение

## ★ (2 балла): валидация и пагинация

- Проверяются все поля, ошибки приходят в формате `{"error": "текст", "field": "имя поля"}` с кодом 400.
- Список умеет фильтр и пагинацию: `?limit=10&offset=0&<поле>=<значение>`.

## ★★ (2 балла): документация и логи

- Документация OpenAPI (Swagger UI) по адресу `/docs`.
- Каждый запрос пишет строку лога: метод, путь, статус, время в миллисекундах. Например: `GET /api/books/7 404 1.3ms`.

## contract.json

```json
{
  "base_url": "http://localhost:8000",
  "resource": "books",
  "id_field": "id",
  "missing_id": "999999",
  "list_key": null,
  "create": { "title": "Мастер и Маргарита", "author": "Булгаков", "copies": 3 },
  "update": { "copies": 5 },
  "required_field": "title",
  "errors": [
    { "body": { "title": "" }, "field": "title" },
    { "body": { "author": "" }, "field": "author" },
    { "body": { "copies": -1 }, "field": "copies" }
  ],
  "filter": { "param": "author", "value": "Булгаков", "other": "Пушкин" }
}
```

| Поле | Что писать |
| --- | --- |
| `base_url` | Адрес сервиса, обычно `http://localhost:8000` |
| `resource` | Имя ресурса из пути: для `/api/books` это `books` |
| `id_field` | Как называется id в ответе, обычно `id` |
| `missing_id` | id, которого точно нет. Для UUID подойдёт любой несуществующий UUID |
| `list_key` | `null`, если `GET /api/books` отдаёт массив. `"items"`, если отдаёт `{"items": [...]}` |
| `create` | Правильное тело для создания |
| `update` | Какие поля поменять при обновлении |
| `required_field` | Обязательное поле, чекер отправит его пустым и без него |
| `errors` | Только для ★: неправильные значения полей и какое поле должно попасть в ошибку |
| `filter` | Только для ★: параметр фильтра, подходящее и неподходящее значение |
| `openapi_path` | Только для ★★ и только если OpenAPI-описание лежит не на стандартном адресе, например `"/swagger/v1/swagger.json"` |
