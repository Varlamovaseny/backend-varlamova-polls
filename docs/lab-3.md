# Лаба 3. Пользователи и доступ

У сервиса появляются пользователи. Читать данные может кто угодно, изменять только тот, кто вошёл, и только свои записи. Регистрация `POST /auth/register`, текущий пользователь `GET /auth/me`, вход через Basic Auth. Пароль хранится только хэшем bcrypt или argon2. Автора записи (`owner_id`) ставит сервер. Проверка доступа сделана в одном месте: middleware, dependency или фильтр.

Срок: PR из `lab-3` в `main` до 23:59 накануне встречи 4.

## Чек-лист базы (6 баллов)

1. `POST /auth/register` создаёт пользователя, повтор с тем же логином даёт 409
2. Пароли хранятся хэшем bcrypt или argon2
3. Изменения без авторизации дают 401, с Basic работают; неверный пароль даёт 401 без подсказки
4. `GET /auth/me` возвращает текущего пользователя без пароля и хэша
5. Запись привязана к автору, `owner_id` ставит сервер
6. Чужую запись изменить и удалить нельзя: 403

## ★ (2 балла): JWT

- `POST /auth/login` возвращает `{"access_token": "..."}`, запросы с `Authorization: Bearer <токен>` работают.
- Подделанный и просроченный токен дают 401.
- Секрет и время жизни токена берутся из переменных окружения.

## ★★ (2 балла): администратор и лимит попыток

- Роль `admin` может изменять и удалять любые записи. Админ создаётся сидом или из окружения, через регистрацию им стать нельзя.
- После 5 неудачных попыток входа за минуту сервер отвечает 429.

## contract.json: что добавить

```json
{
  "auth": {
    "scheme": "basic",
    "register_path": "/auth/register",
    "login_path": "/auth/login",
    "me_path": "/auth/me",
    "login_field": "username",
    "password_field": "password",
    "token_field": "access_token",
    "owner_field": "owner_id",
    "admin": { "username": "admin", "password": "admin-test-pass" }
  }
}
```

Дополнительные поля регистрации, например email: `"register_extra": {"email": "bc@example.com"}`. Если сразу сделан JWT без Basic: `"scheme": "bearer"`.
